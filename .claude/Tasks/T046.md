# Task 46 – Settings UI: "Load" button for live provider item discovery

Status: **Done**
Source: docs/SPEC.md § Live Provider Item Discovery

## Pre-condition

T045 must be Done: adapter `listAvailable?` methods must exist before the UI can call them.

## Goal

Add a "Load" button to each "Install new" row in the three collapsible settings sections
(Installed translations, Reference formats, Recognition languages) so the user can fetch the
current item list from the selected provider on demand.

## Scope

- In `src/settingsTab.ts`, for each "Install new" row:
  - Insert a **"Load"** button between the provider dropdown and the items dropdown.
  - The button is shown only when the selected provider's adapter implements `listAvailable?`;
    hidden otherwise (check at render time and on provider dropdown change).
  - On click: call the adapter's `listAvailable` (performing the `requestUrl` fetch in
    `settingsTab.ts` or via a thin helper in `src/packManager.ts` / `src/translationManager.ts`);
    repopulate the items dropdown with the returned list; exclude already-installed items.
  - On fetch failure: show an Obsidian `Notice` with a brief error message; retain the
    catalog-based list.
  - The live result is not cached; closing and reopening the settings tab resets to
    catalog-based list.
- Add section description text below the section heading:
  *"Items shown are from the catalog. Click Load to fetch the current list from the provider."*
- Update `docs/TESTPLAN.md` with manual test steps for the Load button.

## Definition of Done

- `npm run ci` passes.
- For `biblens-data` provider: clicking "Load" in each section repopulates the dropdown with
  the live index result (manual test against actual `biblens-data` repository).
- For a provider without `listAvailable` (e.g. `getbible-v2`): the Load button is absent.
- On network failure: a Notice appears and the dropdown retains catalog-based items.
- Reopening the settings tab resets the dropdown to catalog-based items.
