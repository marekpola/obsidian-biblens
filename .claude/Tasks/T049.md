# Task 49 – Remove Advanced (Catalog Management) section from Settings

Status: **Done**
Source: docs/SPEC.md § Settings Changes (0.4) — Settings tab structure

## Goal

Remove the Advanced section from the settings UI and its backing features (catalog update button, auto-update-on-startup toggle). The catalog is loaded transparently on settings-tab open; no manual update action is needed.

## Scope

### Files to modify

- **`src/settings.ts`**
  - Remove `autoUpdateCatalog: boolean` field from `BibLensSettings` interface
  - Remove `catalogLastUpdated: string` field from `BibLensSettings` interface
  - Remove both fields from `DEFAULT_SETTINGS`

- **`src/main.ts`**
  - Remove auto-update-on-startup block (the `if (this.settings.autoUpdateCatalog && isCatalogStale(...))` block)
  - Remove imports of `fetchCatalogUpdate` and `isCatalogStale`

- **`src/settingsTab.ts`**
  - Remove `this.renderAdvanced(containerEl)` call in `display()`
  - Remove `renderAdvanced()` private method
  - Remove `fetchCatalogUpdate` from the import of `./sources/catalogManager`

- **`src/sources/catalogManager.ts`**
  - Remove `fetchCatalogUpdate` export function

- **`src/sources/catalogUtils.ts`**
  - Delete file (`isCatalogStale` and `CATALOG_STALE_DAYS` become unused)

- **`docs/TESTPLAN.md`**
  - Remove the "Advanced" heading reference in test 48a (step 2 mentions the Advanced heading)

- **`docs/DECISIONS.md`**
  - Add a brief decision entry recording that catalog management was removed from the UI (rationale: simplification; catalog is loaded transparently on settings-tab open)

- **`docs/ARCHITECTURE.md`**
  - Remove `src/sources/catalogUtils.ts` from the Module Paths list
  - Remove `autoUpdateCatalog` and `catalogLastUpdated` lines from the `settings.ts` module description
  - Remove `fetchCatalogUpdate` export and its description from the `catalogManager.ts` module description; also remove the `CatalogUpdateResult` type reference that belongs to it
  - Remove the entire "Catalog update (explicit user action OR opt-in auto on startup):" block from the Data Flow section

### What stays

- `loadCatalog` in `catalogManager.ts` — still used by `settingsTab.ts` `display()` to populate provider/item dropdowns in the Install new rows
- All Install new rows and their Download/Load functionality are unaffected

### Migration note

Existing user data may contain `autoUpdateCatalog` and `catalogLastUpdated` keys in saved plugin data. The `Object.assign({}, DEFAULT_SETTINGS, await loadData())` pattern means leftover keys are silently ignored — no migration needed.

## Definition of Done

1. Advanced section no longer appears in the BibLens settings tab
2. `autoUpdateCatalog` and `catalogLastUpdated` removed from settings interface and defaults
3. No startup network activity related to catalog update
4. `fetchCatalogUpdate` and `isCatalogStale` removed from codebase
5. `catalogUtils.ts` deleted
6. `docs/ARCHITECTURE.md` updated: module list, `settings.ts` description, `catalogManager.ts` description, and Data Flow section all reflect removal
7. `docs/DECISIONS.md` entry added
8. `docs/TESTPLAN.md` updated (Advanced heading reference removed from test 48a)
9. `npm run ci` passes
10. Plugin builds successfully
