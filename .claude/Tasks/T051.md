# Task 51 – Fix Load button: tooltip, biblens-data result display, layout

Status: **Next**
Source: docs/SPEC.md § Live Provider Item Discovery

## Goal

Fix three related issues with the Load button in the Install new rows of all three
collapsible sections (Installed translations, Reference formats, Recognition languages):

1. **Tooltip missing** — the Load button has no tooltip explaining its purpose
2. **biblens-data result wrong** — pressing Load when all items from the selected provider
   are already installed shows "All translations installed" (or equivalent) instead of
   listing available items from the live index; the available list should always reflect
   what the provider offers, regardless of installed state
3. **Layout shifts** — when the items dropdown is repopulated with a long name, the row
   expands or shifts; other elements should retain their size

## Scope

### Changes

- **`src/settingsTab.ts`**

  - **Tooltip:** add `.setTooltip('Fetch the current list of available items from the
    selected provider.')` to every Load button (translations, formats, language packs)

  - **biblens-data result:** after a successful live fetch, populate the items dropdown
    with the **full live list** from the provider (all available items), not only uninstalled
    ones. Already-installed items remain excluded only from the static (pre-load) catalog-based
    dropdown, which is the existing filtering behaviour. After Load the dropdown must show
    all provider items; the Download button is a no-op if the item is already installed
    (or: already-installed items are marked but still shown — simpler implementation).
    Recommended approach: after load, filter already-installed ids out and show remaining
    items; if none remain, show a disabled placeholder "All items installed". The current
    issue is that this filtering happens on the live-fetched list as well, which is correct,
    but the placeholder message "All translation installed" replaces the dropdown entirely
    in a confusing way — improve the message or keep the dropdown visible with a disabled
    state.

  - **Layout:** wrap each Install new row in a CSS flex container. Give the items dropdown
    `flex: 1; min-width: 0` so it absorbs available space. Give the provider dropdown,
    Load button, and Download button `flex-shrink: 0` so they keep their natural size.
    No fixed pixel widths. Apply to all three section Install rows.

- **`styles.css`** (create if absent, otherwise add to existing)
  - Add `.biblens-install-row` flex container rule
  - Add `.biblens-install-row .biblens-install-items` rule (`flex: 1; min-width: 0;
    overflow: hidden; text-overflow: ellipsis`)
  - Add `.biblens-install-row .biblens-install-fixed` rule (`flex-shrink: 0`)

## Definition of Done

1. Hovering over any Load button shows the tooltip text
2. After pressing Load on biblens-data when all items are installed, the dropdown shows
   a clear placeholder (e.g. "All items installed") — not a confusingly empty or broken state
3. After pressing Load with items available, the items dropdown is populated with live results
4. Repopulating the items dropdown with a long entry does not shift the provider dropdown,
   Load button, or Download button
5. Layout fix applies to all three sections (translations, formats, languages)
6. `npm run ci` passes
7. Plugin builds successfully
