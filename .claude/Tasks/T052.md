# Task 52 – Implement Beblia listAvailable via GitHub Contents API

Status: **Next**
Source: docs/SPEC.md § Live Provider Item Discovery — beblia-xml paragraph

## Goal

Add `listUrl` and `listAvailable` to the `beblia-xml` translation adapter so the Load button
appears and works for the Beblia Holy Bible XML GitHub source. The implementation reads the
GitHub Contents API to discover all available XML translation files dynamically.

## Scope

### Changes

- **`src/sources/adapters.ts`** — extend `bebliaXml` adapter:

  - Add `listUrl(provider: SourceProvider): string`
    - Returns `https://api.github.com/repos/Beblia/Holy-Bible-XML-Format/contents/`
    - (The `provider.baseUrl` is the raw GitHub URL; the Contents API URL is a fixed constant
      independent of `baseUrl`)

  - Add `listAvailable(raw: unknown): RemoteTranslationEntry[]`
    - Parses the GitHub Contents API JSON response (array of file objects with `name`, `type`)
    - Filters for entries where `type === "file"` and `name` ends with `.xml`
    - Maps each to `RemoteTranslationEntry`:
      - `id`: filename without extension, lowercased (e.g. `"czechekumenickybible"`)
      - `displayName`: filename without extension (e.g. `"CzechEkumenickyBible"`)
      - `language`: `""` (unknown; cannot be derived from filename alone)
      - `remoteId`: full filename (e.g. `"CzechEkumenickyBible.xml"`) — used by `buildUrl`
    - Returns `[]` on parse failure (do not throw; let the caller show the "load failed" notice)
    - **No catalog enrichment here** — the adapter is a pure transform; it has no access to
      catalog context and must not import from `catalog.ts`

  - **Error handling:** HTTP 403/429 from the GitHub API must be handled gracefully by the
    caller (`settingsTab.ts`). The adapter's `listAvailable` only parses; the HTTP call and
    error display are the responsibility of the settings UI load handler (already implemented
    for other adapters — no extra work needed here).

- **`src/settingsTab.ts`** — enrich Beblia live results with catalog metadata:

  - After a successful `bebliaXml.listAvailable()` call, post-process the returned entries:
    for each entry whose `remoteId` matches a `remoteId` in the Beblia provider's static
    `translations` list (from the loaded catalog), replace the entry's `displayName` and
    `language` with the catalog values
  - This single merge pass keeps the adapter pure and catalog awareness in the UI layer,
    which already has the loaded `CatalogData` in scope during the load handler

- **`docs/ARCHITECTURE.md`** — update `adapters.ts` module description:
  - Document that the `beblia-xml` adapter now implements `listUrl` and `listAvailable`;
    note the fixed GitHub Contents API URL and that enrichment is delegated to the caller

### Rate-limit note

The GitHub unauthenticated API allows 60 requests/hour per IP. Load is an explicit user
action, so this limit is acceptable in normal use. No special handling needed beyond the
existing 403/429 error notice.

## Definition of Done

1. Selecting "Beblia Holy Bible XML (GitHub)" as provider and pressing Load fetches the
   GitHub Contents API and populates the items dropdown with discovered XML files
2. Known catalog entries (e.g. `CzechEkumenickyBible.xml`) retain their catalog display name
   and language tag in the list (enrichment applied by `settingsTab.ts` after the adapter call)
3. Newly discovered `.xml` files not in the catalog appear with their filename as display name
4. HTTP 403 or 429 response shows the existing "load failed" notice and retains the catalog list
5. `docs/ARCHITECTURE.md` `adapters.ts` description updated to document `beblia-xml` `listUrl`/`listAvailable`
6. `npm run ci` passes
7. Plugin builds successfully
