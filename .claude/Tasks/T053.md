# Task 53 – Translation priority/abbreviation: settings data model

Status: **Next**
Source: docs/SPEC.md § Translation Display Priority and Abbreviation Settings

## Goal

Introduce `translationOrder` and `translationAbbreviations` fields to plugin settings, retire `preferredTranslation`, and migrate existing data on first load. Update the auto-default mechanism to operate on `translationOrder` instead of `preferredTranslation`.

## Scope

- `src/settings.ts`
  - Add `translationOrder: Record<string, number | null>` (default `{}`)
  - Add `translationAbbreviations: Record<string, string>` (default `{}`)
  - Remove `preferredTranslation: string`
- `src/main.ts`
  - On load: if `preferredTranslation` is present in stored data, copy it into `translationOrder[value] = 1` then delete the field; save settings.
  - Replace all reads of `settings.preferredTranslation` with a helper `getActivePriority1Id(settings): string | undefined` that returns the id whose `translationOrder` value is `1`.
  - `reloadTranslation()` (and initial load) uses `getActivePriority1Id` to determine which file to load.
- `src/settingsTab.ts`
  - Auto-default: if `translationOrder` has no entry with value `1` and at least one translation is installed, assign priority `1` to the first installed translation (save + reload). Replace the existing `preferredTranslation` auto-default logic.
  - Remove any reads of `settings.preferredTranslation`.

Out of scope: Settings UI controls (T054), multi-translation loading (T055).

## Definition of Done

- `npm run ci` passes.
- Installing fresh (no prior data): first installed translation receives priority 1 automatically.
- Upgrading from v1.0 data (`preferredTranslation` set): migration runs once, priority 1 assigned to that translation, field removed from stored JSON.
- Plugin loads, hover shows verse text from the priority-1 translation as before.
