# Task 53 – Translation priority/abbreviation: settings data model

Status: **Next**
Source: docs/SPEC.md § Translation Display Priority and Abbreviation Settings
Decision: docs/DECISIONS.md § D032

## Goal

Introduce `translationOrder` and `translationAbbreviations` to plugin settings, retire `preferredTranslation`, perform a one-time migration on first load, and update the auto-default mechanism. Extract all ordering logic to a new pure module `src/translationOrder.ts`.

## Scope

- `src/settings.ts`
  - Add `translationOrder: Record<string, number | null>` (default `{}`)
  - Add `translationAbbreviations: Record<string, string>` (default `{}`)
  - Remove `preferredTranslation: string`

- `src/translationOrder.ts` (new pure module — no Obsidian imports)
  - `migratePreferredTranslation(settings): boolean` — if `preferredTranslation` key exists in settings (from saved data), copy its value to `translationOrder[value] = 1` and delete the key; return `true` if migration was applied, `false` otherwise
  - `getActivePriority1Id(settings): string | undefined` — returns the id whose `translationOrder[id] === 1`
  - `getActiveTranslations(settings, allData: Record<string, TranslationData>): { id: string; abbreviation: string; data: TranslationData }[]` — returns entries from `allData` whose id has a priority number in `translationOrder`, sorted ascending by priority; abbreviation defaults to the translation `id` when not set in `translationAbbreviations`

- `src/main.ts`
  - On `onload()`: call `migratePreferredTranslation(this.settings)`; if it returns `true`, save settings
  - Replace `translationData: TranslationData` with `allTranslationData: Record<string, TranslationData>` (initially `{}`)
  - Load the priority-1 translation at startup using `getActivePriority1Id` → `loadTranslation` (single load for now; multi-translation parallel load is T055)
  - Replace all remaining reads of `settings.preferredTranslation` with `getActivePriority1Id(this.settings)`

- `src/settingsTab.ts`
  - Auto-default: replace `settings.preferredTranslation === ''` check with: if `translationOrder` has no entry with value `1` and at least one translation is installed, assign priority `1` to the first installed translation (save + `reloadAllTranslations()`)

Out of scope: Settings UI controls (T054), multi-translation parallel loading (T055).

## Definition of Done

- `npm run ci` passes.
- Fresh install (no prior data): first installed translation receives priority 1 automatically via auto-default.
- Upgrade from v1.0 (stored `preferredTranslation` present): migration runs once on `onload`, priority 1 assigned to that translation, `preferredTranslation` absent from saved JSON afterwards.
- Plugin loads and hover shows verse text from the priority-1 translation as before.
- `src/translationOrder.ts` has no `obsidian` import.
