# Task 55 – Multi-translation data loading

Status: **Next**
Source: docs/SPEC.md § Multi-Translation Hover Pop-up

## Goal

Extend `main.ts` to load and cache `TranslationData` for all priority-numbered translations (not just priority 1). Provide a typed map of active translations to downstream consumers (hover, tooltip, insert commands).

## Scope

- `src/main.ts`:
  - Replace the single `translationData: TranslationData` field with `allTranslationData: Record<string, TranslationData>` — keyed by translation id, contains only translations with a priority number set (ordered by priority for convenience).
  - On `onload()`: load all priority-numbered translations via `loadTranslation` in parallel (`Promise.all`); populate `allTranslationData`.
  - `reloadTranslation()` (or a new `reloadAllTranslations()`): re-runs the same parallel load and updates `allTranslationData` in-place.
  - Helper `getActiveTranslations(settings): { id: string; abbreviation: string; data: TranslationData }[]` — returns entries from `allTranslationData` in priority order, each paired with the configured abbreviation. Used by hover, tooltip, and insert commands.
  - Existing single-translation consumers (`refTooltipExtension`, `insertAfterLastRefCommand`, `replaceLastRefWithQuoteCommand`) are updated to receive the new ordered list type (or a backwards-compatible shim for the single-translation case) in preparation for T056 and T057.

Out of scope: DOM changes (T056), insert command text changes (T057).

## Definition of Done

- `npm run ci` passes.
- With one priority-numbered translation: behaviour identical to v1.0.
- With two priority-numbered translations: both `TranslationData` objects loaded at startup.
- After `reloadAllTranslations()` (triggered from settings save): updated map reflected in hover and tooltip without plugin restart.
