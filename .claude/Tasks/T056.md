# Task 56 – Multi-translation verse DOM

Status: **Next**
Source: docs/SPEC.md § Multi-Translation Hover Pop-up

## Goal

Add `buildMultiTranslationDOM` to `verseDOM.ts` for stacked and paged multi-translation layouts, and wire it into the editor tooltip and Reading View hover.

## Scope

- `src/ui/verseDOM.ts` (no Obsidian imports):
  - Keep `buildVerseDOM(entries: VerseEntry[]): HTMLElement` unchanged — single-translation path is preserved exactly.
  - Add `buildMultiTranslationDOM(blocks: { abbreviation: string; entries: VerseEntry[] }[], refFormat?: ReferenceFormatRules): HTMLElement`:
    - **Determine layout** by total verse count across all blocks:
      - **Stacked** (single verse / single-chapter ref — all blocks have ≤ 1 entry OR all entries belong to a single chapter): each block rendered as one line `<sup>abbr label</sup> text`; blocks separated by `<hr>`.
      - **Paged** (multi-verse or chapter-range — any block has > 1 entry): one page per block; each page contains the block's content built via the existing `buildVerseDOM` logic; a page heading `<div>` shows the abbreviation; `<button>` prev / `<button>` next switch pages by toggling CSS `display`; page state initialised to first block.
    - Empty `entries` in a block: render the abbreviation heading only, no verse text, no error.
    - All DOM via `createElement`/`textContent`; no `innerHTML`.
  - **Copy button** (D017): out of scope for this task — deferred to a follow-up task after multi-translation layout stabilises. The existing `buildVerseDOM` copy button path is unaffected.

- `src/editor/refTooltip.ts`:
  - Update factory signature: `refTooltipExtension(activeTranslations: { id: string; abbreviation: string; data: TranslationData }[], refFormat?: ReferenceFormatRules): Extension`
  - When `activeTranslations.length === 1`: call `buildVerseDOM` (unchanged path).
  - When `activeTranslations.length > 1`: call `buildMultiTranslationDOM`.
  - **Paged view caveat**: CM6 `hoverTooltip` dismisses on mouse-leave from the token range; if paged navigation buttons are not reliably reachable in the tooltip DOM, use stacked layout for multi-verse refs in the editor tooltip only (paged layout limited to Reading View). Developer must verify reachability during implementation and document the outcome in the task file.

- `src/main.ts` (Reading View hover):
  - For each active translation, call `getVerses(data, ref, refFormat)` to build the `entries` array.
  - When 1 active translation: call `buildVerseDOM(entries)` (unchanged).
  - When 2+ active translations: assemble `blocks` array and call `buildMultiTranslationDOM(blocks, refFormat)`.

## Definition of Done

- `npm run ci` passes.
- Single active translation: hover and editor tooltip identical to v1.0.
- Two active translations, single verse ref: stacked pop-up with abbreviation prefix and `<hr>` separator.
- Two active translations, multi-verse ref: paged pop-up with prev/next navigation; page heading shows abbreviation; resets to first page on each new pop-up.
- Translation with no verse found: shows abbreviation heading only; no error text.
- No `innerHTML` in new DOM code.
- docs/TESTPLAN.md updated with multi-translation hover test cases.
