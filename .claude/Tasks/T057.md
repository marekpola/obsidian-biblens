# Task 57 – Multi-translation insert commands

Status: **Next**
Source: docs/SPEC.md § Insert Commands — Multi-Translation Behaviour

## Goal

Update the two insert command factories in `insertVerse.ts` to use the ordered active translations list (from T055). `insertAfterLastRefCommand` uses priority-1 only; `replaceLastRefWithQuoteCommand` iterates all active translations.

## Scope

- `src/editor/insertVerse.ts`:
  - `insertAfterLastRefCommand`:
    - Signature change: accepts `{ abbreviation: string; data: TranslationData }[]` (ordered active translations); reads only the first entry (priority 1).
    - Inserted text: ` — abbr verse text` (abbreviation prefix added).
    - When list is empty or priority-1 entry missing: no-op.
  - `replaceLastRefWithQuoteCommand`:
    - Signature change: same ordered list type.
    - Iterates all entries in priority order; for each, calls `getVerses`; if result is non-empty, appends a `> abbr Ref verse text` line.
    - Translations with no verse text are silently omitted.
    - When list has exactly 1 entry: output is a single `> abbr Ref verse text` line (same as v1.0 except abbreviation prefix added).
  - Module remains pure (no Obsidian imports).

- `src/main.ts`:
  - Pass the ordered translations list (from `getActiveTranslations`) to both command factories.

## Definition of Done

- `npm run ci` passes.
- `Insert verse after previous reference`: inserts priority-1 abbreviation + verse text; unchanged when only one translation active (except abbreviation prefix).
- `Replace previous reference with quote`: one `> abbr ref text` line per active translation in priority order; missing verses omitted; single-translation output is one line.
- `insertVerse.ts` has no `obsidian` import.
- docs/TESTPLAN.md updated with multi-translation insert test cases.
